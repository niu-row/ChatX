GETTING STARTED

ChatX 使用教程

先理解连接原理，再完成安装、授权和 ChatGPT 端的使用。正常配置一次后，日常只需要启动 ChatX。

HOW IT WORKS

工作原理

ChatGPT发起工具调用
→
OpenAI Secure Tunnel安全转发 MCP 流量
→
ChatX127.0.0.1:3210/mcp
→
你的电脑文件 / Git / Shell

ChatX 本身只在本机监听。 Node MCP 后端监听 127.0.0.1:3210，不会直接把本地端口暴露到公网。

tunnel-client 主动建立安全连接。 Tunnel ID 用来指定要连接的 Secure MCP Tunnel，Runtime API Key 用来授权 tunnel-client 建立这条连接。

权限最终由本机 ChatX 执行。 即使 ChatGPT 请求读取某个文件，ChatX 仍会检查“允许目录”和文件/Git/Shell 权限。关闭某个权限后，相应调用会在本机被拒绝。

桌面版只是控制层。 Tauri 负责窗口、托盘、目录选择和启动后台组件；真正的 MCP 工具仍由本地后端执行。关闭主窗口只会隐藏到托盘，不会中断 Tunnel。

FIRST SETUP

第一次配置

1

获取并填写 Tunnel ID

打开 OpenAI Platform 的 Tunnels 页面，创建或选择一个 Secure MCP Tunnel，然后把以 tunnel_ 开头的 Tunnel ID 直接粘贴到下面。这里与“连接”页面完全同步，不需要来回切换。

2

获取并填写 Runtime API Key

创建一个给 Tunnel 使用的 Runtime API Key，复制后直接粘贴到下面。建议使用受限 Key，只给 Tunnel 所需权限。这里输入的 Key 同样会同步到“连接”页面。

3

选择权限模式

日常代码项目建议使用“开发”模式。它允许文件和常规 Git 修改，但默认关闭 Shell、完整文件系统和高级 Git。需要更高权限时再单独开启。

4

选择允许目录

点击“选择文件夹”，添加 ChatGPT 真正需要访问的项目目录，例如 E:\Source\AI\chatgptx。建议按项目授权，不要为了方便长期开启“完整文件系统访问”。

5

连接并运行诊断

上面的 Tunnel ID 和 Runtime API Key 填好后，可以直接在教程里启动。连接页仍然保留，两个页面显示和操作的是同一套连接配置。

CHATGPT SETUP

在 ChatGPT 开启开发者模式并添加 ChatX

先确认套餐和权限。 当前完整 MCP（包含写入/修改操作）主要面向 Business、Enterprise 和 Edu 的开发者模式；Pro 可在开发者模式连接自定义 MCP，但目前以读取/fetch 能力为主。受工作空间管理的账号还需要管理员授予相应权限。

1. 开启开发者模式。 打开 ChatGPT 设置，进入 Apps → Advanced Settings 开启 Developer mode；部分工作区当前也可能在 Security and login 中显示该开关。工作空间管理员还可能需要先在 Workspace Settings → Permissions & Roles 中允许 Connected Data Developer mode / Create custom MCP connectors。不同账号的入口可能因灰度发布略有不同。

2. 打开 Plugins / Apps 创建页。 进入 ChatGPT Plugins，点击 ＋ 创建 developer-mode app。应用名称填写 chatx，这样聊天里就可以清楚地以 @chatx 识别它。

3. Connection 选择 Tunnel。 不要填写本机的 127.0.0.1:3210。选择 Tunnel，从列表选择 ChatX 正在使用的 Tunnel；如果列表里没有，也可以直接粘贴 tunnel_...。本地 MCP 不需要暴露公网。

4. 扫描工具并创建。 点击 Scan Tools，确认能够扫描到 ChatX 的工具（例如 server_info、文件、Git、Shell 工具），然后点击 Create。创建完成后，它会出现在 Settings → Apps → Enabled Apps，开发版通常会带 Dev 标记。

5. 如果 Tunnel 看不到。 检查 Tunnel 是否关联到了当前 ChatGPT workspace，而不仅仅是 Platform organization；创建应用的账号还需要 Tunnels Read + Use 权限。ChatX 桌面端也必须保持 Tunnel 为 running。

ChatGPT 的 Apps / Plugins / Developer mode 界面仍在迭代，名称和入口可能变化。若你更新了 ChatX 的工具定义，已发布应用不会自动采用新工具；需要在 ChatGPT 端刷新/审核应用工具。

USE IN CHATGPT

在 ChatGPT 里怎么使用

确保 ChatX 正在运行，并且 Secure Tunnel 状态为 running。如果 ChatGPT 中已经添加了你的 ChatX 连接器，就可以在对话中直接调用它。

你当前的用法就是最直接的一种：在消息中写 @chatx，然后说明要操作的本地文件、Git 仓库或命令。

查看项目@chatx 列出 E:\Source\AI\chatgptx 的目录结构
读取文件@chatx 读取 package.json，解释每个 npm script 是做什么的
修改代码@chatx 修改这个项目的 Tauri 界面，然后运行测试
检查 Git@chatx 看一下当前 git diff，告诉我这次改了什么
运行命令@chatx 在项目目录运行 npm test

“运行命令”需要 Shell 权限；写文件需要“修改文件”；Git 提交等写操作需要 Git 写入。权限不足时，ChatX 会拒绝对应调用，而不是自动扩大权限。

DAILY USE

日常使用方式

启动：安装后直接从开始菜单或桌面快捷方式打开 ChatX，不会出现 CMD 窗口。

最小化：点击系统最小化按钮会正常进入 Windows 任务栏。

关闭窗口：点击右上角关闭不会退出程序，而是隐藏到系统托盘，Tunnel 和本地 MCP 继续运行。

恢复：左键点击托盘中的 ChatX 图标，或右键选择“打开 ChatX”。

真正退出：右键托盘图标选择“退出 ChatX”。这时桌面程序才会关闭自己启动的 Tunnel 和本地后端。

TROUBLESHOOTING

常见问题

ChatGPT 说无法访问某个目录

先检查“权限 → 允许目录”。目标文件必须位于已授权目录内，除非你明确开启了“完整文件系统访问”。

可以读文件，但不能修改

检查当前权限模式是否为“安全”。切换到“开发”，或在高级权限里开启“修改文件”。

不能运行 npm / python / 其他命令

Shell 默认关闭，因为它不受允许目录沙箱约束。只有确实需要执行本机命令时再开启 Shell。

Tunnel 一直无法连接

确认 Tunnel ID、Runtime API Key 是否匹配，运行“诊断”查看 tunnel-client 和 readyz 状态。也可以重新创建受限 Runtime Key 后再连接。

点关闭后为什么进程还在

这是设计行为：关闭窗口等同于隐藏到托盘。要彻底退出，请使用托盘菜单中的“退出 ChatX”。

推荐配置

日常开发：使用“开发”模式 + 明确的项目允许目录；Runtime Key 用 DPAPI 保存；Shell、完整文件系统和高级 Git 默认保持关闭，需要时临时打开。
